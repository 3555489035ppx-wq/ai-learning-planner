# 假期跃迁产品逻辑

## 1. 计划不是待办清单

系统帮助用户判断优先级、把可执行任务放入当前自然周，并在中断后继续安排。任务数量和课表填满程度都不是产品目标。

## 2. 四层计划模型

| 层级 | 模型 | 回答的问题 |
|---|---|---|
| 内容进度 | `LearningStageDefinition` | 这门课现在学什么、完成什么后进入下一阶段？ |
| 待安排工作 | `TaskPoolItem` | 还有哪些未完成任务等待安排？ |
| 具体安排 | `TaskPlacement` | 任务在哪一天、哪个 Slot 执行？ |
| 周视图 | `WeeklySchedule` | 当前自然周安排了什么，哪些任务仍在 backlog？ |

阶段不以固定结束日期使任务失效。旧任务中的阶段日期仅用于历史兼容和审计。

## 3. 排程

- 4＋4＋2 是每天的可用 Slot 容器，不要求填满。
- Task Duration 是预计时长；只要不超过 Slot 时长，短任务可正常排入长 Slot。
- 默认排程只安排目标自然周，放不下的任务留在 Task Pool/backlog。
- backlog 是可恢复信息，不阻止本周课表启用。
- 旅行、休息日、明确不可用时间、Slot 冲突、无效引用和非法任务是阻断规则。
- 严格假期范围和严格每日容量是用户显式启用的高级约束，不是默认启用条件。

## 4. 诊断与置信度

- 成绩或自评可以生成基线计划，但不能直接证明具体知识点掌握情况。
- 未完成客观基础诊断时，成绩型课程保持低或中等置信度，取决于课程信息和证据完整度。
- 完成诊断会提高定位依据，不自动保证高置信度或学习结果。

## 5. Evidence、复盘与恢复

- 预计时长与实际学习时长分开保存。
- 完成、延期、跳过、测验、资源完成和反思都以事件或 Evidence 保存。
- 计划中断时，未完成任务回到 Task Pool，并保留原任务 ID 与语义键。
- Recovery 提供减负、延长周期、重新平衡优先级或保持计划等选项；用户确认后生成 ChangeSet，并可撤销。

## 6. 课程隔离

课程、诊断、任务、资源、Evidence、进展和复盘均以 `courseId` 绑定。不同课程不能串用知识点、资源或任务内容。
