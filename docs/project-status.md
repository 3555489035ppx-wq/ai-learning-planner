# 项目当前状态报告

更新日期：2026-08-21

## 项目判断

当前仓库已经不是静态页面 Demo，而是一个可在浏览器本地运行的前端 MVP：它包含课程上下文、诊断、计划版本、Task Pool、自然周排程、今日执行、Evidence、周复盘、Plan Recovery、ChangeSet 撤销和数据迁移。

当前最适合公开展示的定位是：

> AI Learning Planner · 假期跃迁：一个用本地规则模拟 AI 决策的 Personal Learning System 作品集 Demo。

## 技术与运行状态

| 项目 | 当前状态 |
| --- | --- |
| 前端 | React 19 + Vite 8 + TypeScript 7 |
| 路由 | React Router，包含首次规划、诊断、计划、今日、资源、进展、周复盘和设置 |
| 数据 | localStorage、本地 schema 迁移、导出/导入 |
| AI/计划 | 可替换 provider 接口；当前为本地 mock provider |
| 资源 | 人工审核目录、用户链接、原平台打开；不抓取第三方视频 |
| 部署适配 | Vercel SPA fallback、Cloudflare Pages `_redirects` |
| 默认状态 | 新浏览器使用空白用户数据；首页按钮加载独立 Demo 数据 |

## 已完成内容

- 高中生 Demo：六门课程存在差异化成绩、诊断依据和 30 天任务。
- 课程隔离：课程、知识点、资源、任务和进展都绑定 `courseId`。
- 解释性规划：任务可查看知识点、安排原因、优先级、预计时间、资源和完成标准。
- 计划恢复：未完成任务回到任务池，恢复方案可预览、确认并撤销。
- 排程容错：阶段描述学习进度，课表使用自然日期；backlog 不阻断计划启用。
- 桌面端与移动端无页面级横向溢出，核心流程有自动化回归。

## 明确边界

- “AI”是产品流程和 provider 抽象的设计位置；当前输出由本地规则生成，不是远程大模型结果。
- 诊断使用成绩、自评、任务和测验等结构化证据；没有真实用户研究或成绩提升证明。
- 资源推荐只使用项目内人工审核条目和合法外链；检索建议不等于已验证资源。
- 线上公开 URL、GitHub 推送和部署凭据不写入仓库，也不在本地自动伪造。

## 发布前剩余动作

1. 在 GitHub 创建只包含本项目的公开仓库，并确认仓库名称与署名。
2. 将本地提交推送到 GitHub，检查 README 图片和链接在远端正常显示。
3. 在 Vercel 或 Cloudflare Pages 使用仓库构建 `pnpm run build`，输出目录为 `dist`。
4. 用无痕窗口验证公开地址的首次空白状态、Demo 入口和 SPA 深链接。
5. 将真实公开地址补入根 README 的 “GitHub 与部署” 小节。
